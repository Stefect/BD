# Сутності

- **Товар (Product):** назва, артикул (SKU), одиниця вимірювання, мінімальний поріг залишку, опис
- **Постачальник (Supplier):** назва компанії, контактна особа, номер телефону, email, адреса
- **Локація складу (WarehouseLocation):** унікальний код комірки (location_code), зона, номер ряду/стелажа/полиці, максимальна місткість
- **Накладна постачання (SupplyOrder):** номер документа, дата надходження, статус обробки, підсумкова сума, посилання на постачальника
- **Позиція накладної (SupplyItem):** посилання на накладну, посилання на товар, кількість, ціна закупівлі
- **Залишок на локації (InventoryStock):** посилання на товар, посилання на комірку зберігання, поточна кількість товару на цій локації
- **Внутрішнє переміщення (InventoryMovement):** посилання на товар, комірка відправлення, комірка прийому, кількість, дата та час операції

# Унікальні ключі

- **Product:** id (*UUIDv7*), sku_code (*Unique Key*)
- **Supplier:** id (*UUIDv7*), email (*Unique Key*)
- **WarehouseLocation:** id (*UUIDv7*), location_code (*Unique Key*), складена унікальність (zone, shelf_number)
- **SupplyOrder:** id (*UUIDv7*), order_number (*Unique Key*)
- **SupplyItem:** id (*BigSerial*)
- **InventoryStock:** id (*BigSerial*), складена унікальність (product_id, location_id)
- **InventoryMovement:** id (*BigSerial*)

# Припущення

- Первинними ключами для основних довідникових сутностей (Master Data: Product, Supplier, WarehouseLocation, SupplyOrder) обрано UUIDv7 для забезпечення часового сортування, безпеки та масштабованості.
- Для транзакційних таблиць та високонавантажених логів (SupplyItem, InventoryStock, InventoryMovement) використано тип BigSerial задля збереження обсягу пам'яті та швидкодії індексів B-Tree.
- Поле `total_cost` у `SupplyOrder` розраховується як сума добутків `quantity * unit_price` усіх пов'язаних рядків `SupplyItem` (денормалізоване поле для прискорення аналітичних вибірок).
- Для миттєвого отримання поточного стану залишків у кожній комірці виділено окрему сутність `InventoryStock` (операційний зріз залишків), що позбавляє від необхідності важкої агрегації по всій історії переміщень.
- Якщо партія товару списується або видається за межі складу, `to_location_id` в сутності `InventoryMovement` може приймати значення `NULL`.
- Позиції в накладній `SupplyItem` після отримання статусу `received` не підлягають прямому редагуванню — коригування залишків дозволяється лише через `InventoryMovement`.
